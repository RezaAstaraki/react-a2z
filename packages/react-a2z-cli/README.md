# react-a2z-cli

Copy editable React A2Z component source into your project. The component code
lives in your project, so you can customize it directly.

## Requirements

- Node.js 18 or newer.
- An existing React project with Tailwind CSS **v3.4.1+ or v4** already installed and configured.

The CLI detects the installed Tailwind version before writing anything. For v3,
it copies token CSS and a local preset, adds that preset to your existing Tailwind
config, and extends its content paths. For v4, it copies `@theme` mappings and
explicit source paths, importing them after Tailwind. It does not upgrade
Tailwind or replace your PostCSS setup. Dependency installation uses
`tailwind-merge` v2 for Tailwind v3 and v3 for Tailwind v4.

## Install a component

Run from your app's root directory:

```bash
npx react-a2z-cli@latest init
npx react-a2z-cli@latest add select
```

This checkout supports **Select**, **ColorPicker**, and **GradientMaker** using
`add select`, `add color-picker`, and `add gradient-maker`. Each command also
initializes the project if needed; run a separate command for each component.

The color tools are new checkout additions. The commands above use the published
release; `npx ...@latest` does not run local changes. Before a release includes
the color tools, run them directly from the library repository:

```sh
npm run registry:build
node packages/react-a2z-cli/bin/cli.js add color-picker --cwd ../my-app --dry-run
node packages/react-a2z-cli/bin/cli.js add color-picker --cwd ../my-app
node packages/react-a2z-cli/bin/cli.js add gradient-maker --cwd ../my-app
```

Replace `../my-app` with your existing React/Tailwind app. You can also use the
linked local command described below. These commands do not publish anything.
The installer adds `clsx` and `tailwind-merge`. It selects npm, pnpm, Yarn, or
Bun from the invoking package manager's environment (`npm_config_user_agent`),
falling back to npm. It does not select a package manager from lockfiles alone.

When your app has a `src` directory, it creates:

- Select: `src/components/ui/select.tsx` and `field.tsx`
- ColorPicker: `src/components/ui/color-picker.tsx`
- GradientMaker: `src/components/ui/gradient-maker.tsx`
- `src/lib/react-a2z/cn.ts` and `extend-merge.ts`
- Color tools share `color.ts`, `use-controllable-state.ts`, and
  `hex-color-input.tsx` in the same helper folder. GradientMaker also adds
  `copy-to-clipboard.ts`. Either color tool can be installed on its own.
- `src/styles/react-a2z.css`
- `a2z.json` with the configured paths

For apps without `src`, it uses `components/ui`, `lib/react-a2z`, and `styles`
at the project root. Existing `a2z.json` paths take precedence.

It adds a style import to an existing global stylesheet, including Next App
Router/Pages Router and Vite conventions. Use `--css` for other locations.
If no configured Tailwind stylesheet is found, it stops before writing files.
You do not need to install the `react-a2z` runtime package.

For example, from a file directly inside `src` (or the project root in an app
without `src`):

```tsx
import { Select } from "./components/ui/select";
import { ColorPicker } from "./components/ui/color-picker";
import { GradientMaker } from "./components/ui/gradient-maker";
import type { GradientValue, GradientMakerClassNames } from "./components/ui/gradient-maker";
```

Adjust the relative import for your file's location. Generated components and
helpers use TypeScript, including when the app's entry point uses JavaScript.

This checkout's GradientMaker source has three built-in presets, ordered Sunset
Orange, Ocean Blue, then Rainbow. Omit `presets` for these defaults; `[]` hides
the choices. Thumbnails stay at their own angle or 90 degrees, while selecting
a preset without an angle preserves the editor angle. These local changes are
not a claim about the published `@latest` release. The documentation app's live
Tailwind compiler is separate from installed components: consumer classes are
generated by the consumer's own Tailwind build.

The current local source also supports adding, removing and reordering color
stops. It appends white, retains at least one stop, and preserves the existing
`GradientValue` shape (`{ colors, angle }`). `maxColors` limits adding to 1–32
(default 32), without truncating existing values or presets. Set
`showColorActions={false}` to hide the actions. New action/header/status slots
are included in `GradientMakerClassNames`; no new shared helper is required.
Regenerate and use the checkout CLI to install this unpublished update.

The local source also includes a numeric angle editor (whole degrees 0–360
update live; Enter/blur finishes the edit, Escape clears invalid drafts) and
undo/redo for up to 50 gradient edits. Slider gestures and numeric editing
sessions each form one undo step; external controlled values reset history.
`showAngleNumber` and `showHistory` default to true. All new controls expose
typed classNames/styles slots; no extra shared helper is required.

Preset `name` is optional. Set `showPresetNames` (default false) to display
supplied nonblank names inside thumbnails. Style each label through
`classNames.presetName` or `styles.presetName`; `preset` styles the button.
Unnamed presets keep numbered accessible labels and have no visible name.

History buttons accept `undoLabel`/`redoLabel` (empty strings hide visible text),
`undoIcon`/`redoIcon` (React nodes, or null to hide), and `undoAriaLabel`/
`redoAriaLabel` for accessible names. Separate icon/label classNames and styles
slots keep these parts customizable without replacing the button behavior.

## Options

```bash
npx react-a2z-cli@latest --help
npx react-a2z-cli@latest add select --dry-run
npx react-a2z-cli@latest init --path src/components/custom-ui
npx react-a2z-cli@latest add select --cwd ./my-app
npx react-a2z-cli@latest init --css src/custom.css --tailwind-config config/tailwind.config.ts
```

- `--dry-run`: preview paths without writing files or installing dependencies.
- `--skip-install`: use dependencies you have already installed without running a package manager.
- `--overwrite`: allow replacing the requested component source; existing components are protected by default. Component replacement does not make backups. Color tools preserve existing shared helpers even with `--overwrite`, so installing one never discards edits made while using the other.
- `--path`: set the component directory during initial setup.
- `--cwd`: use a different app directory.
- `--css`: select an existing global Tailwind stylesheet.
- `--tailwind-config`: select an existing Tailwind v3 config when it has a custom path.

## What `a2z.json` does

This file tells future CLI commands where your generated source and Tailwind
setup live. It is installer metadata; your React app does not read it at runtime.
Commit it with the generated source. A typical Tailwind v3 app with `src` has:

```json
{
  "components": "src/components/ui",
  "utils": "src/lib/react-a2z",
  "styles": "src/styles/react-a2z.css",
  "css": "src/app/globals.css",
  "tailwindVersion": 3,
  "tailwindConfig": "tailwind.config.ts"
}
```

Paths are relative to the app root. `styles` is the generated stylesheet;
`css` is your existing global stylesheet that imports it. Tailwind v4 records
`tailwindVersion: 4` and does not need `tailwindConfig`.

Prefer `--path`, `--css`, and `--tailwind-config` during initial setup. Editing
paths later changes where future commands look and write; it does not move
existing files or rewrite all your app imports. Move files and update imports
when changing an established layout. Use `repair` after a Tailwind major change
so the CLI detects and records the installed version.

## Repair an existing setup

If an earlier CLI generated v4 styles in a v3 app, or you change Tailwind major
versions, preview and repair the setup:

```bash
npx react-a2z-cli@latest repair --dry-run
npx react-a2z-cli@latest repair
```

Repair preserves your component files and existing helper source. It updates the
managed style block, preset/config wiring, metadata, and matching dependencies.
Changes outside the managed style block are retained. Existing changed files get
`.a2z-backup` copies. Unrecognized/custom styles or presets require an explicit
`--overwrite` after review; components are still preserved by `repair`.

Restart a running dev server after repair so it reloads Tailwind configuration.
Updating the CLI alone does not refresh source already copied into your app.
To refresh a color component, review your edits and run its `add` command with
`--overwrite`. Shared helper changes require a separate manual review/merge;
neither component overwrite nor `repair` replaces those edited helper files.

For Tailwind v3, initial setup also creates a local preset at
`lib/react-a2z/tailwind.preset.cjs` (under `src` when present) and its TypeScript
declaration. The existing Tailwind config imports this preset and scans your
generated source directories.

The CLI parses JavaScript/TypeScript Tailwind configs without executing them.
CommonJS exports, default exports, and a config variable are supported. Existing
theme, plugins, presets, and content entries are retained. Dynamic exported
configs or dynamic arrays, prefixed classes, and selector-scoped `important`
require manual integration; the CLI stops before writing files. A missing React
project, unsupported Tailwind version, or unconfigured global CSS also stops
before writing. A dry run creates no files and installs no dependencies.

## Test the local CLI before publishing

From a full repository checkout, install development dependencies and run:

```bash
npm ci
npm run cli:test
npm run cli:apps:prepare
npm run cli:apps:check
```

The maintainer suite requires Node 22.12+ and tests a freshly packed local CLI,
including TypeScript and production builds. See the [starter app guide](../../tests/cli-apps/README.md)
for interactive demos, reports, and commands for running that candidate manually.
`npx react-a2z-cli@latest` runs the published release rather than your local edits.

For a globally available local command, run `npm run registry:build` from the
repository root, then `npm link` inside `packages/react-a2z-cli`. From an existing
React/Tailwind app you can then run:

```bash
react-a2z-cli --help
react-a2z-cli add select --dry-run
react-a2z-cli add color-picker --dry-run
react-a2z-cli add gradient-maker --dry-run
```

Rebuild the registry after changing copied components or the registry builder.
`npm link` uses this checkout directly; the packed-candidate suite additionally
checks what the npm package actually contains. None of these commands publishes.

## Publishing (maintainers)

The library (`react-a2z`) and installer (`react-a2z-cli`) are separate npm packages
with independent versions. Publishing the library does not publish the installer.
See the repository's [versioning checklist](../../RELEASING.md) when choosing a bump.

From the **repository root**, preview the CLI package:

```bash
npm run cli:check
```

Then publish the CLI:

```bash
npm run release:cli
```

The CLI's `prepack` hook rebuilds its registry from the current library source,
runs CLI integration tests, and compiles the generated styles with real Tailwind
v3 and v4 before npm packs or publishes it. A failed build or test prevents
publishing. You do not need to run `registry:build` separately when publishing.
These commands must run from a full repository checkout; consumers do not need
the build scripts to use the published CLI.

The fast checks cover both color-tool install orders, standalone installs,
root/custom directories, dry runs, collision protection, repair, preserved
shared helpers, and consumer TypeScript checks for all three components with
Tailwind v3/v4. Templates are generated from library source rather than edited
independently. The twelve-app suite also renders the installed color tools in
fresh production builds.

The twelve-app suite is a separate maintainer command; publishing does not run
it automatically. Run `npm run cli:apps:check` before a CLI release. The library's
API/version gate applies to `react-a2z`; CLI checks do not automatically classify
its version bump.

For subsequent CLI releases, bump only its version before publishing:

```bash
npm --prefix packages/react-a2z-cli version patch --no-git-tag-version
npm run release:cli
```

Use a minor version for compatible features and a major version for breaking
changes after reaching 1.0.0. During 0.x development, use a minor bump for breaking
changes. New CLI releases do not require a library version bump.
